# v0.2.0 发布验证

本版本只发布 Windows x64 电脑版和网页版。发布日志见 [版本历史](release-notes.md)。

## 验证范围

- 四个 package.json、Cargo.toml/Cargo.lock、Tauri 应用配置统一为 `0.2.0`。
- 本地 TypeScript、ESLint、Prettier 通过；共享 81 项、Web 131 项、日志提取 5 项测试通过。20 项系统 FFmpeg 集成测试因工具不在 PATH 而跳过。
- Web production 构建通过；源码不带入缓存、依赖、私钥、Android 工程或安装包。
- GitHub CI 不依赖发布签名私钥进行普通安装包构建；正式 Release 始终要求匹配公钥的签名。
- 本地既有签名密钥的配套公钥与应用公钥相同，签名试验成功；不生成或轮换新的密钥。

## 暴露面审计：总览

使用本机 `reverse-engineering-exposure-audit` 扫描器，只读检查当前 Web 产物和保留的 Windows 原生程序。Web 检查 19 个文件、15 个 JS 产物，未发现扫描规则命中。原生基线是保留的 0.1.0 可执行文件，不能当作 0.2.0 最终二进制的验收。

扫描评分为 Web 100/A、旧原生程序 69/C；这是启发式规则计分，不是安全认证。源码公开、前端代码可分析符合 MIT 开源项目定位，不增加混淆或反调试措施。

## 发现清单

| 编号 | 扫描级别 | 发现与人工判断 |
|---|---|---|
| PE-SIGN | 高 | 原生基线没有 Windows Authenticode 证书签名；Tauri 更新签名与 Windows 发布者证书不同，不能互相替代 |
| LEAK-INTRANET | 高 | 命中 `http://localhost:5180`，是已公开 Vite 开发地址，不是内部服务或凭据泄漏；不作为高风险结论 |
| PE-PDB | 中 | CodeView 仅保留 `audio_studio_desktop.pdb` 基名，没有用户目录；PDB 文件不作为发布附件 |
| PE-CFG | 低 | 基线 PE 未声明 Control Flow Guard；属于后续二进制加固方向 |

## 逐项证据与处理

- Web：`build.sourcemap=false`，扫描产物未发现 `.map`、环境文件或高置信度秘密规则命中。
- PE-SIGN：扫描器在基线 `DataDirectory[SECURITY]` 中未见证书。没有配置付费发布者证书，不会声称 Windows 显示受信发布者；正式更新包仍必须有可校验的 Tauri `.sig`。
- LEAK-INTRANET：路径来自已提交的 `tauri.conf.json` 开发 URL；正式程序使用内嵌前端，未将此命中描述为真实内网泄露。
- PE-PDB：仅文件基名，无绝对源码路径，未携带对应 PDB；风险较扫描标签低。
- PE-CFG：未为发布临时改变编译器安全选项，以免引入未经完整验证的链接兼容性变化。

## 客户端无法解决的问题

应用是本地音频工具，没有账户付费授权、远程计费或服务端权限判定。客户端资源和算法可被读取属于开源交付事实。签名私钥只用于打包签名，不能进入客户端或 Git；Web 新版本提示也不能替代服务器部署。

## 修复顺序与后续验收

1. P0：持续避免把私钥和其他秘密放入源码、构建产物或日志；匹配签名缺失时拒绝发布更新。
2. P1：核对 0.2.0 实际发行的版本号、附件、签名配对、清单与 SHA-256；不根据旧原生基线或编译成功推断安装升级成功。
3. P2：有发布者证书后增加 Authenticode；评估 CFG 及更严格的桌面 CSP，分别验证文件预览和平台功能。

旧客户端发现、验签、安装、重启的完整跨版本更新仍需独立实机验收；未将上述静态检查当作该流程通过。
